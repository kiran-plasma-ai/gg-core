# gg-core Registry

Complete architecture overview of gg-core - a minimal Python library for tmux-based AI agent session management.

> **AGENT INSTRUCTION**: When working on gg-core, prefer using the core library functions (start_session, send_command, etc.) over CLI commands for programmatic access. Follow the module structure documented below.

## Module Architecture

| Module | Layer | Purpose |
|--------|-------|--------|
| cleaning | Core | Tmux output cleaning for gg-core. |

| extraction | Core | Core extraction module. |

## CLI Commands

| Command | Description |
|---------|-------------|
| `start` | Start a new session |
| `stop` | Stop a session |
| `ps` | List all sessions |
| `send` | Send a command to a session |
| `logs` | Show session logs |
| `attach` | Attach to a session |
| `connect` | Start and attach to a session |

## Supported Agents

The default agent is `DEFAULT_AGENT` (`$GG_DEFAULT_AGENT`, default `omp`); pass an explicit agent to `gg start`/`gg connect` to override.

| Agent | Default Command |
|-------|----------------|
| omp | `~/.bun/bin/omp -c` |
| kimi | `~/.kimi-code/bin/kimi -c` |
| coder | `~/.cargo/bin/coder -m kimi -S {project} --yolo` |
| grok | `~/.cargo/bin/coder -m grok -S {project} --yolo` |
| minimax | `~/.cargo/bin/coder -m minimax -S {project} --yolo` |
| gemini | `~/.local/bin/gemini` |
| opencode | `~/.local/bin/opencode` |
